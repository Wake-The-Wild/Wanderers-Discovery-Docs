# Create a custom discovery

WD datapacks define **discovery content**, not world generation. The target
structure must already be registered and generated by Minecraft or its supplying
mod. WildTrack observes its starts/pieces; WD attaches names, assets and awards.
Read the [WildTrack boundary](wildtrack-api.md) if your structure does not use
Minecraft's normal registry/start system.

## Minimal pack

Create `pack.mcmeta` using the datapack format supported by your target
Minecraft version. The following concrete example uses the format listed in the
[compatibility reference](compatibility.md); adjust it when targeting another version:

```json
{
  "pack": {
    "description": "My discovery definitions",
    "min_format": [121, 0],
    "max_format": [121, 0]
  }
}
```

Then create `data/examplemod/wanderers_discovery/poi_types/moon_temple.json`:

```json
{
  "structures": ["examplemod:moon_temple"],
  "name": {"fallback": "Moon Temple"}
}
```

The definition ID is `examplemod:moon_temple`. Nested paths are supported; keep
namespace and path stable because the ID is persisted in world history.
Use your own namespace instead of `minecraft`, `wildtrack` or `wanderers_discovery`.

Install in `<world>/datapacks`, enable it, and run `/reload`. Look for loading
warnings if a definition is malformed. At least one structure ID/tag is required.
Reload changes definitions; it does not erase discoveries or replay an already
recorded instance. A renamed ID is a new discovery type, not a migration.

## Matching and overlaps

`structures` accepts IDs and `#tag` entries. `structure_tags` accepts additional
tag IDs. Targets are alternative matches. `detection: "piece"` uses known structure
geometry; `"bounding_box"` uses the actual whole-start bounds and is useful for
spread-out villages. Lower `priority` wins the primary active-location selection;
equal priorities are ordered by definition ID. Custom definitions are checked
before built-in categories. Overlapping newly found locations still queue their
presentations rather than being discarded.

For a modded structure that should behave exactly like a built-in type, use
[category tags](structure-tags.md) instead of inventing a new type.
For different content, use the [full schema](discovery-schema.md).

## Advancements and client assets

An optional `advancement` refers to an advancement supplied by the pack or mod.
WD manually awards **all criteria** after presentation when
`uses_vanilla_advancement` is false. Use a dedicated manually granted advancement
with an `minecraft:impossible` criterion. Set the flag true when another system
already grants it. The field alone does not create an advancement JSON.

Textures, sound files and translations need a [resource pack](resource-packs.md)
or mod client assets. A discovery can reuse installed WD event/texture IDs without
copying their licensed asset files into your pack.

The [ready-to-install example](../examples/README.md) uses a vanilla jungle pyramid
so it works without an imaginary structure mod. Replace its target with your
real registered ID when adapting it.
